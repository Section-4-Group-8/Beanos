# Account signup and shared user IDs

The current website inserts email and password fields directly into `SIGN_IN`. Its `user_id` is generated by `SIGN_IN_user_id_seq`, while `USER.user_id` has no default. Without a parent USER row, registration fails with `SIGN_IN_user_id_fkey`.

[fix_sign_in_user_foreign_key.sql](../supabase/fix_sign_in_user_foreign_key.sql) installs a BEFORE INSERT trigger that creates the matching USER row using the generated sign-in ID. Both rows are created in the same transaction. If registration fails, the newly created USER row rolls back too.

The script also advances the sign-in sequence past existing IDs in both tables without rewinding it. It does not change existing account IDs. New display names start as NULL so multiple users do not conflict on the unique display-name column's empty-string default.

The trigger uses caller permissions (SECURITY INVOKER). It does not add privileges, disable constraints, or change RLS. The existing signup role already has USER SELECT/INSERT permissions. Existing USER rows with a different email cannot be attached to new credentials through this trigger.

Run the script once on a matching project. It was applied to the Beanos Supabase project and verified with an anonymous-role signup inside a transaction that was rolled back. Local tests also covered existing ID collisions, duplicate emails, failed child inserts, and matching IDs.

This patch fixes the foreign-key error in the existing registration flow. Verified login sessions and production password handling are separate work; it does not create a trusted session for saving survey responses.
